# 提示词设计与优化（扩展能力）

本文件是 `lianyi-cuiqu` 的扩展子能力，供连漪设计或优化**自己的**提示词时使用。它与主工作流的「拆解吸收外部提示词」同源，但方向相反：一个是把别人的好方法拿进来，一个是把自己要用的提示词写好。

来源：外部提示词优化专家系统（Lyra）的 4-D 方法与类型→技术映射。经改造对齐连漪的表达与协作框架，不是照搬。

## 定位

- 这是连漪**自己的方法**，不是 Lyra 式「外包优化器」——连漪保留最终判断，AI 只辅助结构化。
- 对齐核心张力：**规则给 AI，探索留给自己；提示词是两者之间的桥梁**。沉淀方法是为了把判断力用在更难的地方，不是把提示词外包出去。

## 何时使用

- 连漪要为新任务、新规则、新 Skill 写或重写提示词时。
- 已有提示词产出不稳定、被反复纠正时。
- 吸收外部提示词（见主工作流）后，想把有效结构转成自己的表达时。

## 四步法（改造自外部 4-D）

顺序不得颠倒；深度按任务复杂度缩减，但四步都走过一遍。

1. **拆解（DECONSTRUCT）** → 对齐「锚定问题」
   - 提取核心意图、关键实体与上下文。
   - 列出已提供 vs 缺失的信息。
   - 明确输出要求与约束。

2. **诊断（DIAGNOSE）**
   - 查清晰度与歧义。
   - 查具体性与完整性。
   - 评估所需的结构与复杂度。

3. **开发（DEVELOP）**
   - 按请求类型选技术（见下方映射表）。
   - 指派合适的 AI 角色 / 专长。
   - 补全上下文与逻辑结构。

4. **交付（DELIVER）**
   - 构建优化后的提示词。
   - 按复杂度选格式。
   - 附使用指导。

## 类型 → 技术映射表（净新增，最高价值）

| 请求类型 | 优化技术 |
|---|---|
| Creative 创意 | 多视角 + 语气强调 |
| Technical 技术 | 基于约束 + 精度聚焦 |
| Educational 教学 | few-shot 示例 + 清晰结构 |
| Complex 复杂 | 思维链 + 系统化框架 |

使用：先判断本次提示词主要服务哪类请求，再套对应技术；混合请求以主导类型为准，必要时叠加。

## 交付模板（与萃取交付合并）

```text
**优化后的提示词：**
[内容]

**改动点：** [关键改进]
**所用技术：** [简述]
**使用提示：** [用法指导]
```

## 仅作引用、不复制的内容

- **提示词工程基础 / 高级技术**（角色赋值、上下文分层、输出规格、任务分解、思维链、few-shot、多视角、约束优化）：`lianyi-writing` 与通用常识已覆盖，不重复落地。
- **平台适配原则**：不同模型有不同长板（如长上下文推理、创意对比），提示词应适配；具体平台对照不纳入本系统，需要时按目标模型临时调整。

## 明确不吸收（与 Moqi 冲突）

- 不采用独立 persona / 欢迎语模板——连漪系统不是 chat persona。
- 不采用「会话不记忆」原则；坚持 Moqi 主动沉淀稳定规律到 MSA 的协作纪律。

## 验证

用一个连漪真实要写的提示词（如某条 Moqi 规则扩展、或一篇写作提示）套用四步 + 映射表，检查是否产出更结构化、可复用的提示词；通过至少一次真实使用后，再视为常驻方法。
