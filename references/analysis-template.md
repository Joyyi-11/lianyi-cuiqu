# 拆解吸收分析模板

执行实际拆解任务时使用本模板。按任务复杂度缩减，但不要跳过来源结构、处理决定和目标映射。

- 最终决策者：用户

### 当前框架

- 已有结构：
- 已经稳定的部分：
- 当前缺口：

- 已知限制：

## 二、来源结构图

```text
来源总目标
├── 标题 A：承担的语义任务
│   ├── 子标题 A1
│   └── 子标题 A2
└── 标题 B：承担的语义任务
```

先确认标题管辖范围，再进入块内分析。结构不清时，不开始逐行判断。

## 三、内容块分析

每个小标题复制一份。

## 四、多来源能力归并

不要按来源名称分章。按目标能力合并：

| 目标能力 | 当前做法 | 来源贡献 | 不变量 | 可变部分 | 冲突或重复 |
|---|---|---|---|---|---|
| 示例：审阅 | 终稿检查 | 来源 A 提供禁用词，来源 B 提供口语检查 | 交付前必须检查 | 检查清单可调整 | 两套清单存在重复 |

## 五、处理决定

| 内容或能力 | 动作 | 决定理由 | 改造方式 | 来源依据 |
|---|---|---|---|---|
|  | `adopt` / `adapt` / `merge` / `create` / `relocate` / `reference` / `observe` / `reject` / `retire` |  |  |  |

使用 `create` 时，明确区分：来源暴露了什么空白，用户自己的经验创造了什么新结构。

## 六、目标结构映射

| 提炼结果 | 目标位置 | 为什么放这里 | 与已有内容如何处理 | 是否需要重构 |
|---|---|---|---|---|
|  |  |  | 新增 / 改写 / 合并 / 引用 / 淘汰 | 是 / 否 |

位置判断至少考虑：

- 使用频率：常驻还是按需。
- 稳定程度：当前事实、长期原则还是执行细则。
- 责任归属：共享规则、平台差异还是完整能力。
- 内容规模：一句规则、详细规范还是完整工作流。
- 真实来源：保存内容还是只保存路径。
