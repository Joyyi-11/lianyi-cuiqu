# 拆解吸收分析模板

执行实际拆解任务时使用本模板。来源既可以是文档、文章或 Skill，也可以是真实使用反馈、对话记录和修改历史。按任务复杂度缩减，但不要跳过来源还原、处理决定和目标映射。

## 二、来源结构图

```text
来源总目标
├── 标题 A：承担的语义任务
│   ├── 子标题 A1
│   └── 子标题 A2
└── 标题 B：承担的语义任务
```

先确认标题管辖范围，再进入块内分析。结构不清时，不开始逐行判断。

实践反馈没有标题结构时，改为还原“任务目标 → 初始做法 → 暴露问题 → 用户纠正 → 修改结果”的过程。每个可独立解释的失败、纠正或判断变化作为一个反馈单元。

## 五、多来源能力归并

不要按来源名称分章。按目标能力合并：

| 目标能力 | 当前做法 | 来源贡献 | 不变量 | 可变部分 | 冲突或重复 |
|---|---|---|---|---|---|
| 示例：审阅 | 终稿检查 | 来源 A 提供禁用词，来源 B 提供口语检查 | 交付前必须检查 | 检查清单可调整 | 两套清单存在重复 |

最终输出也不要默认沿事件发生顺序展开。优先选择目标问题、能力缺口、关键判断或解决路径作为结构轴；个人经历和时间线只承担证据、因果或认知转折功能。

## 六、处理决定

| 内容或能力 | 动作 | 决定理由 | 改造方式 | 来源依据 |
|---|---|---|---|---|
|  | `absorb` / `reference` / `create` / `observe` / `reject` / `retire` |  | 直接采用 / 改造 / 合并 / 换位（仅 `absorb`） |  |

使用 `create` 时，明确区分：来源暴露了什么空白，用户自己的经验创造了什么新结构。

## 七、目标结构映射

| 提炼结果 | 目标位置 | 为什么放这里 | 与已有内容如何处理 | 是否需要重构 |
|---|---|---|---|---|
|  |  |  | 新增 / 改写 / 合并 / 引用 / 淘汰 | 是 / 否 |

位置判断至少考虑：

- 使用频率：常驻还是按需。
- 稳定程度：当前事实、长期原则还是执行细则。
- 责任归属：共享规则、平台差异还是完整能力。
- 内容规模：一句规则、详细规范还是完整工作流。
- 真实来源：保存内容还是只保存路径。

### 结论

来源 `example-writer` 目前是“部分吸收”，不能退役。目标系统已有语言原则，但尚未覆盖“写作姿态 → 深挖过程 → 骨架推进 → 终稿验收”的完整能力链。

### 内容块核销摘要

| 来源内容块 | 当前覆盖 | 动作 | 理由 |
|---|---|---|---|
| 写作姿态 | 原则覆盖 | `absorb` | 已有“诚实表达”，但缺少具体的不确定性表达和不自标深度 |
| 五步深挖 | 文字覆盖 | `absorb` | 目标只写了“连续追问”，没有停止条件和回看原观点 |
| 固定输出格式 | 无覆盖 | `reject` | 属于来源作者的局部工作环境，不适合用户场景 |
| 意外检验 | 未覆盖 | `absorb` | 能检查写作是否产生新认识，符合用户目标 |

### 文件级吸收方案

| 目标文件 | 处理方式 | 具体变化 | 与已有内容的关系 | 验证方式 |
|---|---|---|---|---|
| `references/style.md` | 改写并合并 | 在“诚实表达”下加入：能量化时使用“大概 70%”，不要只写含糊的“可能”；删除“更深地说”等自我宣告 | 改写已有规则，不新增近义章节 | 用一段含模糊判断和深度宣告的文字测试审阅结果 |
| `references/deep-dive.md` | 补全流程 | 加入“说清观点 → 找隐含前提 → 下钻机制 → 到证据边界停止 → 回看原观点” | 扩展现有连续追问，不照搬来源措辞 | 用一个观点检查每一步是否产生新的解释层级 |
| `references/self-check.md` | 新增检查项 | 加入“这次写作发现了什么原本不知道的东西？” | 放入认知结果检查，不混入语言检查 | 对一篇只有流畅表达、没有新发现的文章执行自检 |
| 固定 Org 输出 | 淘汰 | 不吸收 | 与用户主要交付格式冲突 | 无需验证，记录冲突依据 |

### 整体裁决

- 当前状态：部分吸收。
- 保留来源的原因：深挖流程尚未经过真实任务验证。
- 达到退役的条件：完成上述修改，通过至少一个独立写作任务，并确认原 Skill 没有其他独立触发场景或资产。
- 需要用户判断：是否接受量化不确定性的表达方式，以及深挖流程是否进入常驻规则。
