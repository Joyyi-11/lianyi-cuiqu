# 萃取（lianyi-cuiqu）

从外部优秀经验（Skill、提示词、规则文档、文章、工作流、产品方法）中萃取精华，吸收内化进自己的能力框架，持续打磨、提升自己。最终框架必须同时来自用户自己的目标、实践经验、来源中的有效结构，以及用户主动补充的新方法——来源只提供质量参照、可能性和经验，不是标准答案。

## 定位

- 方向：**外部经验 → 自己的框架**（内化）。
- 与 `lianyi-chendian`（自己的实践 → 可复用 skill，外化）方向相反。
- 以用户自己的问题为判断主体，不对每项内容照搬。

## 六种处理决定

| 决定 | 含义 |
|---|---|
| `absorb` | 纳入目标框架（直接采用、改造、合并或换位） |
| `reference` | 不复制内容，只保留真实来源或路径 |
| `create` | 来源暴露缺口，由用户经验和判断创造新解法 |
| `observe` | 证据不足，暂入观察列表，附待验证假设与触发条件 |
| `reject` | 与用户目标、场景或价值冲突 |
| `retire` | 曾适用但已过时 / 重复 / 被替代；停止引用并记录理由（删除来源文件是独立红线，需单独授权） |

## 工作流（硬约束：顺序不得颠倒）

```
锚定自己的问题和目标缺口
  → 建立质量参照（来源是否值得研究、综合还是专项）
  → 枚举来源文件、记录或版本
  → 还原来源结构（标题层级 / 任务阶段）
  → 逐个内容块或反馈单元核销
  → 还原内容块之间的流程和依赖
  → 与目标框架逐块对照
  → 按能力跨来源归并
  → 形成吸收方案
  → 判断整体状态和退役条件
```

步骤 6（融入目标框架）和步骤 8（真实使用验证）仅在执行任务时必做，纯分析任务可标暂缓。先完成来源审计，再做能力归并——不能因 README 声称已整合、某个文件内容相同或核心思想已出现，就推断整个来源已被吸收。

## 目录结构

```
lianyi-cuiqu/
├── SKILL.md                  # 萃取技能定义与工作流
├── agents/
│   └── openai.yaml           # 引用本技能的 agent 配置
└── references/
    ├── analysis-template.md  # 执行任务时读取：核销表与退役门槛模板
    ├── case-studies.md       # 按需读取：边界、反例与方法来源
    └── prompt-design.md      # 按需读取：设计 / 优化连漪自己的提示词
```

## 角色分工

- **AI**：搜索和读取真实来源、按内容块精读、识别能力与缺口、提出处理决定与验证方案、保留来源 / 推测 / 用户决策之间的边界。未经确认不修改目标文件。
- **连漪**：定义什么好、判断哪些适合自己、用经验补充来源未覆盖部分、决定最终系统长什么样。不替连漪作最终取舍。

## 裁决优先级

```
用户的目标与最终判断
  > 真实使用反馈
  > 用户长期积累的经验
  > 外部来源的有效结构
  > 来源的具体文字
  > AI 的建议
```
